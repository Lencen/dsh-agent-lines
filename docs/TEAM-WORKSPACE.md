# 团队工作区约定（v0）

> 用途：让看板（以及未来的工具）能**只读**读取工作区里的团队结构与角色卡。
> 边界：本约定**不重新定义**章程内容；现有章程（如 104 线路中心的 `charters/*.md`）已经够用，这里只补最小机器可读字段。

## 1. 目录约定

```text
<teamRoot>/
├── README.md                 # 组织说明/线路表（可选，人读）
├── registry.json             # 注册表：label → 章程/回执（看板只用于发现）
├── charters/<label>.md       # 角色卡/章程（正文，人写）
├── workspaces/<label>/注册回执.md   # 注册回执（可选）
└── 协议/ 复盘/ 公告/ 汇报/ 汇总/    # 可选
```

## 2. 章程（角色卡）模板（v0）

```markdown
# <角色名>（<label>）章程

> 归属：<团队名> · label：<label> · 上级：<manager label> · 版本：v1.0 · 更新：YYYY-MM-DD

## 1. 定位
## 2. 职责
## 3. 标准产出
## 4. 边界（不做什么）
## 5. 质量要求
## 6. 协作接口
## 7. 调度与汇报规则
```

最小补充（相对现有章程，只加不改）：

1. 头部行补 **`label`** 与 **`更新`**（看板用于绑定与来源行）；缺失时看板回退 registry 映射与文件 mtime。
2. **保持上述 7 个小节标题原样**（看板按标题映射；标题没改就不需要重写正文）。
3. `registry.json` 每条记录至少含 `id/label`、`name`、`charter` 路径；其余字段看板不展示为角色定义。

### 2b. 负责人（manager）章程

负责人也是一条 line（label 由 createFrom 指定，默认 manager），因此同样需要角色卡：

```markdown
# 团队负责人（manager）章程

> 归属：<团队名> · label：manager · 上级：用户 · 版本：v1.0 · 更新：YYYY-MM-DD

## 1. 定位
只做需求对接、任务拆解、调度分配与沟通协调，不直接执行具体任务。
## 2. 职责
1) 接收用户需求，确认目标与优先级；2) 把需求拆解成任务并分配给合适的线/成员；3) 调度跨线依赖、协调冲突；4) 跟踪进度、处理升级与验收。
## 3. 标准产出
任务单、分配记录、验收结论、升级与决策记录。
## 4. 边界（不做什么）
不直接执行任务、不替代成员产出。
## 5. 质量要求
交付验收与风险升级，任务来源与决策记录可追溯。
## 6. 协作接口
上游用户；下游各角色线。
## 7. 调度与汇报规则
按优先级分配；阻塞升级给用户。
```

- 文件位置：<teamRoot>/charters/manager.md（或 registry 中 manager 条目指向的路径）；
- 缺失时看板显示「未采集 · 未提供 manager 章程」，不编造；
- 负责人仍不能 retire/hibernate/rebind，身份由 createFrom 固定。

## 3. 看板如何读取（映射与来源）

| 看板区块 | 来源 | 缺失时 |
|---|---|---|
| 身份组：名称 / label / 状态 / 受谁管理 | 章程头部 + lines 表 | 回退 lines.role/title 并标“未采集” |
| 档案信息：角色定义 / 工作定义 / 工作要求 / 约束 | 章程 §1 定位 / §2 职责 / §3+§5 / §4 边界 | 对应小节缺失 → “未采集+原因” |
| 现状：任务数 / 最近活跃 | 官方任务投影 + line_events | 显示“不可得”徽标 |
| 历史：时间线 | line_events + 注册回执 | 空态说明 |

来源行固定显示：`来源：charters/<label>.md · 更新 <日期>`（日期取头部 `更新`，缺失则文件 mtime）。

## 4. registry.json（只做发现）

- 看板只用它做 **label → 章程文件** 的发现；**不把 registry 字段直接当角色定义展示**，避免与章程正文两处口径；
- 推荐字段：`version`、`lines[{ id/label, name, role, charter, receipt? }]`；其余字段（sessionId/agentId 等）看板不展示。

## 5. 缺失与只读规则

- 三种缺失都不冒充：**文件不存在 / 小节缺失 / 读取失败** → 统一“未采集 + 原因”灰底徽标；
- 看板**只读**：不给编辑/跳转编辑入口，最多显示文件路径文本；不写 `charters/`，不改 `registry.json`；
- 章程由管理线 agent 创建与维护；插件与看板都不自动改写。

## 5b. 团队级信息（可选）

可选：团队级信息（工作目标 / 协作流程）来自 `<teamRoot>/README.md` 的两个可选小节 `## 工作目标`、`## 协作流程`；缺失时看板标“未采集”，不编造。

## 6. 与现有章程的关系（不重定义）

- 现有 104 线路中心的章程正文（定位/职责/标准产出/边界/质量要求/协作接口/调度规则）**内容已足够**；
- 本约定只补 3 个小东西：头部 `label` + `更新`、固定小节标题、registry 的 `charter` 路径；
- 旧章程不补也能用：看板按 registry 映射 + 标题匹配，缺什么就标“未采集”，不做迁移。
