它能帮你做什么

不用反复讲背景

每个成员长期保留自己的上下文；新任务直接派给对应角色。

不用自己当调度

负责人拆任务、分工、协调、追进度，你只看最后的汇总。

不用怕关窗口

成员和消息保存在本地；重启 DSH 后还能接着做。

适合什么团队

不限于开发。小说、视频、研究、运营都可以；只换角色和任务，不需要改插件。

小说团队

总编、大纲、写手、编辑、校对、审读。

视频团队

负责人、策划、脚本、剪辑、封面、发布。

开发团队

负责人、开发、测试、验收。

第一次不需要自己想清楚角色。你只说“帮我建个小说创作团队，按小说创作的流程建立工作流程与机制”，负责人会先给团队结构和流程建议。

为什么不是普通多 agent 插件

它只做组织底座，不替你写流程；流程怎么走，由负责人和角色提示词决定。

不是 DAG / 工作流引擎

不内置任务依赖、状态机、自动验收；需要强管控的子任务，交给角色线按需拉起的官方 L3 临时小队，做完即释放。

不是聊天机器人花名册

长期角色线有稳定名字、可换会话、消息邮箱、租约、交接与唤醒；不是只换人设。

组织底座 vs 业务智能

角色 / 消息 / 持久化 / 看板归插件；怎么拆、怎么验收、怎么返工归负责人和角色提示词。

两种用法：只使用 lines 插件，或者再配合 DSH 官方智能体团队插件（DSH内置）

一句话记住：lines 插件 = 长期员工（记得住事、能换人）；DSH 官方智能体团队插件（DSH内置） = 临时帮手（干完就散）。先用哪个都行，下面分开说。

用法一：只使用 lines 插件

只想要“有人长期记得住背景、任务不丢”——够用，最省事。

用法二：lines 插件 + DSH 官方智能体团队插件（DSH内置）

还想让角色偶尔“开几个帮手并行干活”——大活更快，小活不浪费。

怎么选？

先装 lines 插件；以后遇到“一次要写好几章/审好几份方案”，再把 DSH 官方智能体团队插件（DSH内置）装上，用法不变。

用法一：只使用 lines 插件 —— 一个人带一支长期团队

不考虑并行、也不想要任务板，只想要“有人记得住事、任务不丢”，装这一层就够了。

组织效果（只使用 lines 插件）

负责人（你只跟他说目标）
 └─ 角色线：总编 / 写手 / 校对 / 运营…（长期，记得住事、能换人）
      └─ 不额外开临时小队：活由角色线自己做完
背景只讲一次

每个角色有自己的长期记忆；新任务不用再从头解释前情。

任务不会掉

消息存在本地，重启后还在；发出去能查、能确认、能追到“卡在哪”。

人满了能换，角色不换

一个会话快满了，写一张交接单换个新会话，活接着干，记忆不丢。

适合：小说连载、短视频系列、长期开发/研究/运营项目。

一句话价值：把“每次新开对话都重讲一遍”，变成“带一支记得住事的团队”。

用法二：lines 插件 + DSH 官方智能体团队插件（DSH内置） —— 大活并行，小活不折腾

角色偶尔要“一次做很多块”（比如一次写 3 章、一次对比 5 个方案）时，可以让角色在自己会话里临时叫几个帮手并行做，做完就散。

负责人（你只跟他说目标）
 └─ 角色线：写手 / 校对 / 运营…（长期，记得住事）
      └─ 临时小队：需要并行时才开，做完就散
谁干活不用你操心

默认角色自己做（省钱）；遇到“能拆成 3 块以上 / 要多方案对比 / 要独立审读”，才开临时小队。

任务板不用维护两套

官方任务板只读同步过来，不会让你重复录一遍。

成员和消息还是不漏

小队是临时的，角色和历史一直在；换人、重启都不影响。

什么活由角色线（二级）自己做，什么活拆给临时小队（三级）？

角色线自己做（二级）

需要长期记忆的事（接着上次写、口径不能错）；一件小事一个回合能做完；要写同一批文件；要对你做最终验收。

拆给临时小队（三级）

能拆成 3 块以上互不依赖的活（一次写 3 章、一次做 5 个模块）；要多方案对比 / 交叉审查；需要独立的审读或校对；赶时间且并行能明显提前。

一句话原则

默认自己做；只有“拆得开 + 并行真能省时间”才开小队。小队干完就散，角色一直在。

适合：一次写多章、一次审多份方案、多方案对比、赶时间并行。

一句话价值：大活并行省时间，小活不折腾不浪费钱。

边界：DSH 官方智能体团队插件（DSH内置）目前是实验性；任务是只读同步，不回写官方任务板，也不改变 DSH 官方智能体团队插件（DSH内置）的能力边界。本插件是社区插件，不是 DeepSeek 官方产品。

安装：可以让 DSH 帮你装

在 DSH 新会话里说：

帮我检查并安装 GitHub 上 Lencen/dsh-agent-lines 插件。
只从官方仓库或官方 npm 安装，不要从其他 fork 安装。
安装前先告诉我准备执行什么命令，等我确认后再执行。
安装完成后按插件要求加载；如果需要重启 DSH Web，先告诉我重启后打开哪个地址、
怎么新开会话、第一句该说什么，并提醒当前会话会断开；等我确认后再重启。
重启 DSH Web 会让当前会话断开，重启后 agent 无法再自动通知你；重启后的步骤必须写在重启前。
不想让 DSH 装？手动安装命令 
curl -fsSL https://raw.githubusercontent.com/Lencen/dsh-agent-lines/main/install.sh -o install.sh && bash install.sh

安装后必须重启 DSH Web，插件才会生效。

怎么开始（白话）

1. 装好并重启

按上面的方式安装；需要时重启 DSH Web。

2. 新开一个会话

重启后新开会话，对负责人说要建什么团队。

3. 等它给方案

负责人先提团队结构和流程；你确认或补充角色。

直接说：

帮我建个小说创作团队，按小说创作的流程建立工作流程与机制。
或
帮我建个开发团队，按开发流程建立工作流程与机制。

如果你有明确要求，再补一句：

另外加一个校对和一个审读角色。

第一次使用提示词

小说：

帮我建个小说创作团队，按小说创作的流程建立工作流程与机制。
先不要写正文，建好后等我发第一章任务。

视频：

帮我建个视频创作团队，按视频创作的流程建立工作流程与机制。
先不要开工，建好后等我发第一个选题。

开发：

帮我建个开发团队，按开发流程建立工作流程与机制。
先不要开工，建好后等我发第一个需求。

常见问题

会不会很贵？

按实际使用计费；负责人会先提最小可用团队，后续再扩。

关掉会丢吗？

不会，成员和消息保存在本地，重启后还能接着做。

能同时做两个团队吗？

当前一个插件实例只支持一个团队；小说和视频建议分开环境。
